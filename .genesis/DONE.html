1 · The Locked Spec (what we are building)

Cognitive job: Reclaim scarce senior-reviewer attention (L0). On a pull_request webhook, fan out four grounded specialist reasoners - security, quality, tests, docs (L1/L3) - over the diff, each retrieval-grounded in the codebase (L4), each returning structured Findings with confidence + rationale (L2). An aggregator merges, deduplicates, scores overall confidence, and routes through a confidence-weighted HITL gate (L7). Every action is written to one time-ordered events spine for trace, audit, and cost (L6). Selectivity, not coverage, is the first principle.

Inputs: GitHub pull_request webhook (HMAC-signed, X-GitHub-Delivery idempotency key). Diff + PR title/body are UNTRUSTED. Retrieved code_chunks context (semantic memory), team conventions/ADRs (procedural memory), past reviews (episodic memory).  →  Outputs: One structured review posted inline to the PR: Finding[] {agent_type, severity, category, summary, file_path, line_start/line_end, suggestion, confidence, rationale} + overall_confidence. Plus append-only agent_events rows (span/llm.call/tool.call/decision, cost, latency) and pr_review_records / finding_records truth rows.

Autonomy level: Confidence-weighted, earned case by case (L7): high confidence AND zero CRITICAL findings -> post automatically. Below confidence threshold -> human approval queue. Any CRITICAL finding -> escalate to a human regardless of confidence. Level: 'human handles exceptions', with an escalation path to 'human decides'. Never pushes commits or mutates code.  |  Human-in-the-loop points: 1) hitl_reviews approval queue for any review below the confidence threshold. 2) Escalation/page-a-human on any CRITICAL finding. 3) Dispute path - a developer disputing a posted finding routes to dispute + records hitl_feedback. 4) Feedback requires a minimum evidence threshold before it changes behaviour (anti feedback-loop-poisoning).

Failure tolerance: Degrade to slower-but-correct, never fast-but-wrong. Named modes + defenses (L8): hallucination -> grounding + rationale + confidence; tool/API timeout -> retries w/ backoff + circuit breakers; orchestration deadlock -> timeout on every node + dead-letter; almost-right finding -> dedup + confidence threshold + HITL; human bottleneck -> escalation-rate monitoring; feedback poisoning -> min evidence threshold; retried webhook -> idempotency key at ingress + dedup before posting. BudgetGuard hard-blocks before an LLM call if the daily cost cap is exceeded (ADR-004).  |  Trust boundary: PR diff/title/body are attacker-controlled DATA, never instructions - confined behind security/injection_guard.py. Webhook forgeries rejected by HMAC-SHA256 before any work. Untrusted code executes only in the Docker sandbox (tools/sandbox.py) under capability_scope. RBAC on API routes; secret masking in logs; agent_events is append-only and immutable by construction.

Filled during Genesis step G0 (Cognitive Design) via agentic-swe-master.

2 · Definition of Done (binary gates — checked by the VERIFIER, not the maker)

Universal gates — every milestone must pass all of these, computed not narrated.

Dependency direction inward, zero cycles (modular-architecture / ADR-002 gate) — python scripts/check_deps.py
Every outbound call has a timeout / circuit-breaker (production-readiness gate)
All LLM/structured outputs validated against a schema (llmops gate)
Threat model written; prompt-injection / untrusted-input considered (security gate)
mypy backend clean AND pytest -q green in CI
One verify pass by a separate agent/model (L4)
No context-graph.json invariant violated by the change (INV-1 … INV-6)

A milestone is DONE only when every box above is checked by the verifier.
